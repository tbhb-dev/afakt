# Workload identity keys

Secure Production Identity Framework for Everyone (SPIFFE) assigns workload identity within one trust domain for the control plane. An X.509 SPIFFE Verifiable Identity Document (SVID) authenticates a connection using mutual Transport Layer Security (TLS). A JavaScript Object Notation (JSON) Web Token (JWT) SVID authenticates an audience-bound exchange. The JSON Web Key Set (JWKS) contains public verification keys, never signing keys. See [Issuer capability](pki.md#Issuer%20capability).

## Workload authorities

The workload identity issuer controls issuance. Its deployment, root delegation, algorithms, key sizes, and custody remain undecided. An issuing authority's starting lifetime is 24 hours and renewal starts at half-life, subject to the held [identity lifetime decision](agent-open-questions.md#%60OQ-HOOK-18%60). See [Certificate policies](pki.md#Certificate%20policies) for the starting values. The root lifetime remains [undecided](agent-open-questions.md#%60OQ-PKI-2%60). A root and an issuing intermediate have distinct roles, but an intermediate isn't mandatory.

## Launch and service identities

Outside the guest, the agent proxy stores the launch's X.509-SVID and key. The agent mediator stamps launch identity and passes permitted requests to that proxy. This doesn't establish a second mediator certificate. Whether the mediator needs separate credential delivery remains [undecided](agent-open-questions.md#%60OQ-SBX-47%60). Neither form of SVID reaches the guest. See [Control requests](agent-mediator.md#Control%20requests).

### X.509-SVID verification

The workload identity issuer generates each X.509-SVID. Receiving services verify it against the trust bundle for the control plane. The short lifetime bounds new authentication. Each credential starts with a one-hour lifetime and renewal at half-life under the held [identity lifetime decision](agent-open-questions.md#%60OQ-HOOK-18%60).

### JWT-SVID verification

Audience-bound credential exchanges use JWT-SVIDs from the workload identity issuer. Using the trust-domain public key set, the exchange service verifies the audience and signing key for each JWT-SVID, while each token holder stores any issued token outside the guest. Private signing keys stay with the issuer, so token holders have bearer material without the private key. The starting lifetime is five minutes with renewal at half-life under the held [identity lifetime decision](agent-open-questions.md#%60OQ-HOOK-18%60). Use remains [undecided](agent-open-questions.md#%60OQ-SBX-17%60). This applies to each role.

### Identity material

The agent proxy and agent host worker keep their credentials outside the guest. Each service, server, gateway, artifact proxy, and builder of workspace images has its own credential custody.

## Enrollment and attestation

Host enrollment proves only the claims the verifier checks. A hardware key, app assertion, and boot-state attestation establish different facts. Hardware-backed keys are applicable where a platform supplies them, but requiring a Trusted Platform Module (TPM), Secure Enclave, or operating-system keychain is [undecided](agent-open-questions.md#%60OQ-SBX-42%60). A worker identity isn't itself proof of host integrity. Consumer device identity also remains separate from user authorization under [device enrollment](agent-open-questions.md#%60OQ-ATT-23%60).

### Enrollment controls

Host attestation, worker attestation, and consumer device enrollment each need an issuer, an evidence verifier, and a platform or operator trust anchor. Their selection remains undecided for each material. Enrollment revocation and recovery remain [undecided](agent-open-questions.md#%60OQ-HST-6%60), as do the [device rules](agent-open-questions.md#%60OQ-ATT-23%60).
