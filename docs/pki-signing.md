# Signing keys and secrets

Signing authority is separate from workload connection identity. The Application Programming Interface (API) server authenticates users and signs session messages. It also issues scoped registry credentials. Brokered upstream credentials stay outside the agent sandbox. JavaScript Object Notation (JSON) Web Token (JWT) and JSON Web Signature (JWS) formats use public verification keys. A JSON Web Key Set (JWKS) publishes those keys without private material. See [Message signatures](agent-session-attachment.md#Message%20signatures) and [Credential custody](workload-sandbox.md#Credential%20types%20and%20custody).

## User authentication

User authentication includes `afakt auth login` tokens, browser sessions, and personal access tokens (PATs). Their cryptographic profiles, storage, lifetimes, and rotation remain [undecided](agent-open-questions.md#%60OQ-PKI-3%60). Authentication never replaces session or target authorization. Preview cookies apply only to the exact preview host, while API and dashboard cookies are host-only and never scoped to a parent of preview hosts. See [HTTP previews](workload-previews.md#HTTP%20previews).

Session cookies and opaque tokens are secrets, not certificates. Whether a cookie or token uses a signature, a keyed hash, encryption, or server-side lookup remains [undecided](agent-open-questions.md#%60OQ-PKI-3%60). A public key set has no private-key custody or independent signing algorithm. Its profile follows its associated signer. [Share-link checks](workload-previews.md#Access%20and%20share%20links) don't grant access beyond the selected port.

## Service signing

The registry verifies each request's bearer token against the control plane's published keys, issuer, registry audience, validity interval, and repository and action scopes. Workers renew tokens through the control plane when a transfer outlasts their validity. The API server separately signs session messages and retains retired public message keys for as long as it retains messages. The [macOS virtual-machine provider](workload-provider-macos-vm.md#Platform%20dependencies) needs authorized virtualization entitlements. An entitlement isn't a separate private key. Which capabilities attach to each release artifact remains [undecided](agent-open-questions.md#%60OQ-PRQ-7%60).

The [Windows host provider](workload-provider-windows-host.md#Platform%20dependencies) requires driver signing and distribution qualification for its WFP callout driver. Windows platform signing and driver submission aren't macOS notarization. Certificate selection, submission credentials, signing service custody, timestamp validation, update trust, and compromised-release withdrawal remain [undecided](agent-open-questions.md#%60OQ-PKI-8%60).

## Secret storage
