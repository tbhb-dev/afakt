# Glossary

[Public key infrastructure](pki.md).

- **ACP adapter**: the agent harness's Agent Client Protocol (ACP) agent inside the agent sandbox. See [Parts](agent-acp.md#Parts).
- **ACP relay**: the guest relay inside the workload guest that acts as the ACP client to the adapter and uses the workload proxy under mediator decisions. Its [connection owner](agent-open-questions.md#%60OQ-SES-17%60) remains open. See [ACP relay](components.md#ACP%20relay).
- **afakt MCP server**: the built-in Model Context Protocol (MCP) server whose tools call afakt operations with the agent launch’s own authority. Profiles allowlist its tools like any other server. See [Built-in afakt MCP server](agent-mcp-gateway.md#Built-in%20afakt%20MCP%20server).
- **afakt-agent**: afakt's cross-harness runner. For locally controlled execution, it starts afakt-sandbox and runs the agent harness inside it. Hosted agent loop integration remains [`OQ-SBX-63`](agent-open-questions.md#%60OQ-SBX-63%60). In host modes, it runs directly on the workload host. See [Enforcement](workload-sandbox.md#Enforcement).
- **afakt-sandbox**: afakt's cross-platform process sandbox. afakt-agent starts it to confine the agent harness, and it also runs on its own to confine a command that `afakt agent exec` runs in an agent's workspace. See [Enforcement](workload-sandbox.md#Enforcement).
- **Agent change request**: a proposal by an agent or a human to alter an agent spec. Another agent reviews an agent's request, and the control plane applies it within a ceiling the operator sets. See [Agent change request](agent.md#Agent%20change%20request).
- **Agent snapshot**: a portable Open Container Initiative (OCI) image with workspace and harness layers. See [Snapshot contents](agent.md#Snapshot%20contents).
- **Workspace snapshot**: a disk-only capture. See [Snapshot contents](agent.md#Snapshot%20contents).
- **Harness snapshot**: a capture of harness configuration and state. See [Snapshot contents](agent.md#Snapshot%20contents).
- **Agent checkpoint**: a session-level capability through which the agent harness takes its own checkpoint or rewinds session state. It's separate from a workload snapshot. See [Agent checkpoints](agent.md#Agent%20checkpoints).
- **Agent dispatcher**: the Temporal workflow that authorizes an agent launch request and picks a host task queue. It finalizes the agent launch spec and queues the agent launch. In typical use, it starts as a child of the caller's workflow. Temporal dispatches tasks to workers. The agent dispatcher makes app authorization, placement, and configuration choices. See [Agent dispatcher](components.md#Agent%20dispatcher).
- **Agent fork**: a separate agent copied from another agent, with its own identity. See [Agent fork](agent.md#Forks).
- **Agent group**: a named set of agents with membership, metadata, events, and broadcasts. See [Agent group](agent.md#Agentmail,%20groups,%20and%20subscriptions).
- **Agent harness**: the agent program whose locally controlled execution runs inside an agent sandbox. Hosted agent loop placement remains [`OQ-SBX-63`](agent-open-questions.md#%60OQ-SBX-63%60). Examples include Claude Code and Codex. See [Agent harness](agent-launch.md#Parts).
- **Workload host registry**: the Application Programming Interface (API) server's record of the workload hosts that can run agent launches. Each entry gives a host's task queue, lower and upper slot capacity bounds, current slot capacity, most recent capacity change reason, and host metadata, and it lasts while the host's worker renews its lease. See [Workload host registry](workload-placement.md#Workload%20host%20registry).
- **Workload host worker**: the daemon that runs the agent launcher workflow on a workload host and connects it to the control plane. See [Workload host worker](components.md#Workload%20host%20worker).
- **Workload host**: a machine that runs workloads for afakt. Use workload host for this machine. Host alone requires unambiguous context and an earlier workload host in the same section. See [Workload host](workload-host.md).
- **Agent launch request**: a request by an agent, human, or automation to use an existing agent or an ephemeral agent to perform a task. Task completion deletes the ephemeral agent. See [Agent launch request](agent.md#Agent%20launch%20request).
- **Agent launch result**: the terminal state, payload, evidence references, and provenance record an agent launch ends with. See [Agent launch result](agent-launch-contract.md#Agent%20launch%20result).
- **Agent launch slot**: one place for a reserved or claimed agent launch on a workload host. The reservation API counts both kinds against slot capacity. See [Slot reservations](workload-placement.md#Slot%20reservations).
- **Agent launch spec**: the finalized, immutable configuration of an agent instantiation on a workload host. It records the agent spec generation used for finalization and never changes during the agent launch. See [Agent launch spec](agent-launch-contract.md#Agent%20launch%20spec).
- **Agent launch**: one instantiation of an agent in an agent sandbox on a workload host, linked to its predecessor on retry, resume, migration, or crash recovery. See [Agent launch](agent-launch.md).
- **Agent launcher**: the workflow that takes an agent launch spec and acquires an agent sandbox through the workload provider the spec names. It starts the agent harness and waits before tearing down. See [Agent launcher](components.md#Agent%20launcher).
- **Workload proxy mediator**: the workload component that decides connections and messages without transmitting traffic. It controls DNS through the proxy, with no host fallback, and stamps launch identity. See [Workload proxy mediator](components.md#Workload%20proxy%20mediator).
- **Agent profile**: a blueprint for creating an agent, with configuration templates for its agent harness, model, credential authorizations, MCP servers, agent harness plugins, agent skills, agent sandbox, and system instructions. See [Agent profile](agent-profile.md).
- **Workload proxy**: the workload component on the guest data path in both directions. It has its own overlay node and authenticates peers. Each connection requires a mediator decision. See [Workload proxy](components.md#Workload%20proxy).
- **Workload provider**: the adapter that provisions, restores, and releases a workload on a platform. See [Workload provider](agent-launch-contract.md#Workload%20provider%20operations).
- **Workload sandbox**: an `afakt-sandbox` process and the isolation boundary it applies. Agent sandbox and app sandbox refer to the corresponding workload types. See [Workload sandbox](workload-sandbox.md).
- **Agent session workflow**: the entity workflow that holds a session's control state. This includes the lifecycle and writer as well as the attached clients. See [Agent session](components.md#Agent%20session).
- **Agent session**: the agent's conversation. Its transcript remains after an agent launch ends. Interactive attachment uses ACP with writer and reader roles. See [Agent session](agent-session.md).
- **Workload snapshot**: a capture of the memory and disk of the VM an agent sandbox runs in, used to restore it. Host modes and container managers have none. Where afakt needs both VM and harness session state, it takes a workload snapshot and an agent checkpoint together at the same idle turn boundary. See [Workload snapshots](agent.md#Workload%20snapshots%20and%20the%20snapshot%20registry).
- **Agent spec**: the mutable desired configuration of an agent, typically created from an agent profile. Changes always create a generation and replace the agent launch at a turn boundary. An agent never edits its own spec. See [Agent spec](agent.md#Agent%20spec).
- **Agent workspace**: the filesystem mounted into an agent sandbox. See [Agent workspace](agent-workspace.md).
- **Agent**: a durable entity representing the identity, configuration, and history of an artificial intelligence (AI) model. Its lifecycle has one or more agent launches, with at most one running at a time. See [Agent](agent.md).
- **AgentLaunch resource**: the resource form of one agent launch, with its specification under `spec` and the provider's record under `status`. See [Agent launch resource](agent-launch-resource.md).
- **Agentmail**: messaging addressed to durable agents. It includes incoming and outgoing mail with message verification. Delivery and signing semantics remain open. See [Agentmail](agent.md#Agentmail,%20groups,%20and%20subscriptions).
- **API server**: the component serving afakt's Representational State Transfer (REST) API to app clients through the ingress gateway and to coordination workflows. It authenticates workload proxies over the overlay and exposes remote-control and session routes whose [connection owner](agent-open-questions.md#%60OQ-SES-17%60) remains open. See [API server](components.md#API%20server).
- **Archive**: workload snapshot storage for a stopped agent running in a VM whose durable resource enters the archived state. See [Archive](agent-lifecycle.md#Archive%20and%20restore).
- **Artifact proxy**: the service that serves stored artifact content. See [Artifact proxy](components.md#Artifact%20proxy).
- **Artifact**: stored content used as input or output, with optional associations to agents. See [Artifact](agent.md#Memory,%20skills,%20and%20artifacts).
- **Budget**: an agent-level bound on allowed spending or consumption across its work. See [Budget](agent.md#Budgets%20and%20usage).
- **Capability**: one afakt API operation that an agent profile allows an agent to call through the afakt CLI or built-in afakt MCP server. An example is `pull-requests.review`. See [Capabilities](agent-profile.md#Capabilities).
- **Capacity controller**: the part of a workload host worker that measures host resource use and adjusts slot capacity between configured bounds to meet resource targets. See [Slot capacity](workload-placement.md#Slot%20capacity).
- **Component that runs the harness (name undecided)**: the component inside the guest's `afakt-agent` command that runs and talks to the harness program through ACP or by running it headless to print output. The [component and mode names](agent-open-questions.md#%60OQ-SES-12%60) are undecided.
- **Credential broker**: a host-side component outside the guest that injects credentials into permitted requests outside the guest. Reflected response content remains [`OQ-SBX-26`](agent-open-questions.md#%60OQ-SBX-26%60). Its placement relative to the workload proxy and workload proxy mediator remains [open](agent-open-questions.md#%60OQ-SBX-23%60). See [Credential brokering](workload-sandbox.md#Credential%20brokering).
- **Credential**: authenticated service access described by secret material and authorization rules, loaded into a credential broker by reference. See [Credential](agent.md#Secrets,%20credentials,%20and%20trust%20material).
- **Forwarded port**: a record of an agent launch's loopback listener, with its number, name, protocol, state, and first-seen time. See [Port discovery and records](workload-ports.md#Port%20discovery%20and%20records).
- **GitHub webhook receiver**: the component that accepts webhook deliveries from GitHub. See [GitHub webhook receiver](components.md#GitHub%20webhook%20receiver).
- **Guest relay**: the helper for agent session traffic, command-line interface (CLI) and MCP control, and authorized listener streams, using the selected provider’s control carrier. See [Guest relay](components.md#Guest%20relay).
- **Harness event**: a hook event inside the harness, such as `tool-call-before`. The agent harness runs its hooks through the afakt CLI. See [Hook events](agent-hooks.md#Hook%20events).
- **Harness permission**: one kind of action that an agent profile lets the harness offer the agent. An example is editing files. See [Harness permissions](agent-profile.md#Harness%20permissions).
- **Harness transport**: the `acp` or `headless` path selected by an entry in a profile's models. See [Harness transport](agent-profile.md#Harness%20transport).
- **Hook event**: the moment at which a hook runs. It's a provider event or a harness event. See [Hook events](agent-hooks.md#Hook%20events).
- **Hook**: a command from an agent profile or an agent launch spec that runs inside the agent launch's sandbox on a hook event. A hook for a harness event can return a decision such as `deny`. See [Agent hooks](agent-hooks.md).
- **Host-level network service**: the workload host's connectivity role for workload ports, previews, services, and cluster services under host-level authorization. Its mechanism is undecided. See [Host-level network service](components.md#Host-level%20network%20service).
- **Image build**: one agent launch-like job for a workspace image definition. It runs the steps in a profile sandbox and publishes the resulting directory tree as image layers. See [Build process](agent-workspace-image.md#Image%20builds).
- **Index**: registered content organized for retrieval by agents. Its source and query contract remains open. See [Index](cli.md#Configuration%20and%20indexing).
- **External ingress gateway**: the Traefik gateway with afakt authentication middleware that receives user-facing traffic. See [External ingress gateway](workload-overlay.md#External%20ingress%20gateway).
- **Layer cache**: the worker's local store of verified image layer blobs keyed by digest, with a cache of unpacked layers for reuse in independent agent workspaces. See [Workload host caches and startup](agent-workspace-image.md#Workload%20host%20caches%20and%20startup).
- **MCP gateway**: afakt’s single MCP endpoint for each agent launch or session harness, enforcing tool access, credential isolation, approvals, and audit. It doesn't serve outside MCP clients. See [Agent MCP gateway](agent-mcp-gateway.md).
- **Memory**: knowledge retained for reuse across an agent's sessions. Operations support storage and query. See [Memory](agent.md#Memory,%20skills,%20and%20artifacts).
- **Organization**: a grouping of managed work and its access scope. See [Organization](agent.md#Policies,%20roles,%20and%20organizational%20scope).
- **Overlay node**: a workload proxy or workload host or control plane service instance in the private cluster overlay. See [Overlay node](components.md#Overlay%20node).
- **Placement**: the binding of an agent launch to one workload host and its host task queue before launch. See [Workload placement](workload-placement.md).
- **Policy proposal**: a proposed policy change with explicit approval or rejection. See [Policy proposal](agent.md#Policies,%20roles,%20and%20organizational%20scope).
- **Policy**: authorization rules associated with roles, credentials, or sandbox configurations. See [Policy](agent.md#Policies,%20roles,%20and%20organizational%20scope).
- **Port forwarder**: the function that connects authorized publications to guest loopback listeners. Its [path through the workload proxy](agent-open-questions.md#%60OQ-PORT-14%60) remains open. See [Port forwarder](components.md#Port%20forwarder).
- **Preheating**: pulling and unpacking a published image into chosen workload hosts' caches before agent launches need it. See [Placement and preheating](agent-workspace-image.md#Placement%20and%20preheating).
- **Preview server**: a client of published ports that dials the target workload proxy directly over the overlay for authorized preview viewers. The [published-port path](agent-open-questions.md#%60OQ-PORT-14%60) remains open. See [Preview server](components.md#Preview%20server).
- **Preview**: an HTTP view of one forwarded port through an authenticated control plane uniform resource locator (URL). See [HTTP previews](workload-previews.md#HTTP%20previews).
- **Profile binding**: an agent's association with the profile used as a blueprint for its spec. See [Profile binding](agent.md#Owned%20resources).
- **Profile catalog**: the central store of published agent profile versions. See [Profile sources](agent-profile.md#Profile%20sources).
- **Profile resource**: the `AgentProfile` resource form of an agent profile, which repository profile files and the profile catalog both use. See [Profile resource](agent-profile.md#Profile%20resource).
- **Project**: a grouping of work within organizational scope. See [Project](agent.md#Policies,%20roles,%20and%20organizational%20scope).
- **Provenance record**: the record of what an agent launch requested and what the provider observed, in separate fields. See [Provenance record](agent-launch-model.md#Provenance%20record).
- **Provider event**: a hook event whose hooks the workload provider runs itself: `before-agent`, `stop-requested`, `sandbox-violation`, `session-end`, `after-agent`, or `before-teardown`. See [Hook events](agent-hooks.md#Hook%20events).
- **Publication**: an authorized port exposure recording a preview name, agent, port, agent launch ID, and workload host. See [Publication](workload-ports.md#Port%20discovery%20and%20records).
- **Quarantine**: a network condition that removes network access from a running agent without changing its lifecycle state. See [Quarantine](agent-lifecycle.md#Agent%20states).
- **Reconciliation**: the rule that an attempt resolves an existing agent launch through status before it provisions an agent sandbox. See [Reconciliation after restart or retry](agent-launch.md#Reconciliation%20after%20restart%20or%20retry).
- **Registry**: the Open Container Initiative (OCI) distribution component for storing and serving workspace images. It checks repository and action scopes. Upstream base caching and collection of unreferenced content also belong to it. It's distinct from the workload host registry. See [Registry](agent-workspace-image.md#Registry).
- **Repository profile**: an agent profile defined in a YAML Ain't Markup Language (YAML) file under `.afakt/agent-profiles/` in a source repository, versioned by commit. See [Repository profile files](agent-profile.md#Repository%20profile%20files).
- **Request**: a record of work to perform. Closure is complete or incomplete and includes a reason. See [Request](agent.md#Policies,%20roles,%20and%20organizational%20scope).
- **Reservation API**: the API server's operations that match placement requirements against the workload host registry and reserve, claim, and free agent launch slots. See [Reservation API](workload-placement.md#Reservation%20API).
- **Retention hold**: a marker that keeps an agent launch's agent workspace and evidence past its retention period. See [Evidence, retention, and cleanup](agent-launch-model.md#Evidence,%20retention,%20and%20cleanup).
- **Role**: an authorization resource grouping policies and credential grants. Its relationship to the agent launch reporting label remains open. See [Role](agent.md#Policies,%20roles,%20and%20organizational%20scope).
- **Sandbox configuration**: the network, filesystem, and isolation rules that confine an agent. Agent profiles and agent launch specs both contain one. See [Sandbox configuration](workload-sandbox.md#Sandbox%20configuration).
- **Sandbox variable**: a `${name}` placeholder that the provider of the agent sandbox replaces with a value about the agent launch. Sandbox rules, capability scopes, hooks, and workload environment values accept them. See [Sandbox variables](workload-sandbox.md#Sandbox%20variables).
- **Workload guest**: a workload's virtual machine on a VM provider. It supplies a guest kernel and contains the guest relay and workload process. See [Workload guest](components.md#Workload%20guest).
- **Secret**: a stored sensitive value, separate from the credential that describes how to use it. See [Secret](agent.md#Secrets,%20credentials,%20and%20trust%20material).
- **Share link**: a grant to one forwarded HTTP port for a signed-in recipient. It expires and permits revocation. See [Access and share links](workload-previews.md#Access%20and%20share%20links).
- **Skill**: reusable instructions and supporting resources associated with an agent. See [Skill](agent.md#Memory,%20skills,%20and%20artifacts).
- **Slot capacity**: the number of agent launch slots a workload host allows, within its configured lower and upper bounds and reported by its worker to the reservation API. Lowering it leaves existing reservations and running agent launches intact. See [Slot capacity](workload-placement.md#Slot%20capacity).
- **Snapshot registry**: the service that stores and serves workload snapshots of VM state. See [Snapshot registry](components.md#Snapshot%20registry).
- **Standalone sandbox**: a sandbox that runs commands without requiring an agent conversation. See [Standalone sandbox](agent.md#Sandboxes).
- **Subscription**: an event-source association that queues user messages for an agent as deliveries arrive. See [Subscription](agent.md#Agentmail,%20groups,%20and%20subscriptions).
- **Tailnet attachment**: a gateway or optional host-level attachment to a user's tailnet, with no packet routing into the cluster overlay. See [Tailnet attachment](components.md#Tailnet%20attachment).
- **Telemetry endpoint**: the receiver on a workload host for the harness's OpenTelemetry data from the sandbox. It adds the agent launch's identity before forwarding the data. See [Trace context propagation](agent-observability.md#Trace%20context%20propagation).
- **Tool approval**: permission for one pending MCP tool call, answered by a session writer or an agent launch’s unattended profile rule before gateway dispatch. See [Tool approvals](agent-mcp-gateway.md#Tool%20approvals).
- **Tunnel provider**: a built-in connector that publishes an afakt listener on public host names through outbound connections from the control plane. See [Public tunnel providers](workload-previews.md#Public%20tunnel%20providers).
- **Usage**: observed cost, tokens, and subscription consumption across an agent's work. See [Usage](agent.md#Budgets%20and%20usage).
- **VM provider**: the default provider for agent sandboxes, which runs each agent in its own workload guest under the workload host supervisor. See [Workload sandbox](workload-sandbox.md).
- **Web dashboard**: the component that provides afakt's web UI. See [Web dashboard](components.md#Web%20dashboard).
- **Workflow orchestrator**: the component, Temporal, that provides durable execution for afakt's workflows. See [Workflow orchestrator](components.md#Workflow%20orchestrator).
- **Workload**: the execution context plus the workload proxy mediator and workload proxy together with `afakt-agent`. On a VM provider, the context is a workload guest. Other workload providers use a host or container context. A workload can exist without a launch or workspace. It runs exactly one launch before afakt destroys it. A follow-up or relaunch uses a new workload. SPIFFE uses workload for mediators and gateways as well as workers, a distinct meaning. See [Workload](workload.md).
- **Workload identity**: the SPIFFE ID that afakt assigns to a workload and proves with a SPIFFE Verifiable Identity Document (SVID). See [Workload identity](workload-host.md#Workload%20identity).
- **Workspace image builder**: the component that coordinates image builds and publishes successful results. See [Workspace image builder](components.md#Workspace%20image%20builder).
- **Workspace image definition**: the sources, optional base image, steps, agent profile, triggers, destination, and retention settings that describe how to produce a workspace image. See [Workspace image definitions](agent-workspace-image.md#Workspace%20image%20definitions).
- **Workspace image**: an Open Container Initiative (OCI) image whose layers contain a prepared workspace directory tree with checkouts, dependencies, and build outputs. See [Agent workspace image](agent-workspace-image.md).
- **Workspace registry**: the service storing workspace content and revision references for agents and reusable workspace images. See [Workspace registry](components.md#Workspace%20registry).
- **Workspace revision**: a recorded point in an agent's file history, distinct from source repository history. See [Workspace revision](agent.md#Workspace%20revisions%20and%20the%20workspace%20registry).
- **Workspace source**: one `repository`, `image`, `agent-launch`, or `empty` entry that the provider of the agent sandbox places at a target path in the agent workspace. See [Workspace sources](agent-workspace.md#Workspace%20sources).
- **Workload type**: the agent, app, or worker classification, recorded as `type` at creation. See [Creation-time fields](workload.md#Creation-time%20fields).
- **Workload template**: the resource holding creation-time fields, with its version recorded on the workload. See [Creation-time fields](workload.md#Creation-time%20fields).
- **Workload sandbox container**: the container that runs the workload sandbox on a container manager provider. Agent sandbox container and app sandbox container name the corresponding types. See [Workload sandbox](workload-sandbox.md).
- **Workload proxy container**: the container that runs both the workload proxy and workload proxy mediator on a container manager provider. See [Workload proxy](workload-proxy.md).
- **Workload container**: the container inside a workload guest that runs the workload. The names sandbox container, agent container, and app container refer to that context or type. See [Workload guest](workload-guest.md).
- **Workload process**: the main process running inside the workload sandbox. Its type determines whether it's an agent process or an app process. See [Workload sandbox](workload-sandbox.md).
- **Container manager provider**: a workload provider that runs a workload sandbox container and a workload proxy container. Container provider is its shorter name. See [Sandbox modes](workload-sandbox.md#Sandbox%20modes).
- **Host provider**: a workload provider that runs the workload sandbox directly on the workload host, without a workload guest. See [Sandbox modes](workload-sandbox.md#Sandbox%20modes).
- **Remote sandbox provider**: a workload provider that runs the workload in a remote sandbox service. See [Sandbox modes](workload-sandbox.md#Sandbox%20modes).
- **Hosted agent provider**: a workload provider that runs an agent in a hosted agent service. See [Sandbox modes](workload-sandbox.md#Sandbox%20modes).
